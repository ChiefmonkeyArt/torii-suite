**Repo layout reminders.** `installers/` holds the per-stage scripts (`install-nostr-git.sh`, `install-continuum.sh`, `install-ollama.sh`, `install-quest.sh`, `install-bridges.sh`, `register-plebeian.sh`, `rotate-session-secret.sh`, `set-admin-npub.sh`, `torii-deploy.sh`, `torii-quest-update-runner.sh`). `bootstrap.sh` is the top-level orchestrator - env vars flow from `.env` (or CLI) down to the installers. `torii-base` (separate repo, `github.com/ChiefmonkeyArt/torii-base.git`, cloned into `${SUITE_WORK_DIR}/torii-base`) owns the initial nginx sites-available/torii.conf, the `torii` sidecar/CLI, and the main-domain Let's Encrypt cert. Per-app installers just drop nginx fragments into `/opt/torii/nginx-fragments/*.conf` (included from the main vhost) and reload via `/usr/local/bin/torii reload`. **New pattern this slice:** for the relay we go one level up - write a dedicated sites-available vhost, not just a fragment, because a subdomain needs its own server block and its own cert.
